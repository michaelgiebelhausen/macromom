## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can run the app and demo what you've built.
2. **Infrastructure before features.** Phase 0 sets up everything so later feature work is fast and clean.
3. **Magic moment first.** "Open app → here's what to eat at your hall today" works by the end of Phase 3. Everything else builds on it.
4. **Test as you go.** Each task ends with a verification step. Don't defer testing.
5. **Progressive enhancement.** Ship the simplest working version, then layer polish.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review before starting the next phase.
7. **Menu truth is sacred.** Never show or recommend food that isn't actually on today's menu. When data is uncertain, be honest, not confidently wrong.
8. **Keys stay server-side.** All AI/model and email calls go through Supabase Edge Functions. Never bundle secrets in the app.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections — the agent should read only those, not the entire PRD/vision/design docs.
3. **Let it work:** The agent finds the first unchecked task, implements it, marks it `- [x]`.
4. **One session = one phase (ideally):** Complete a full phase per session for continuity; resume from the last unchecked task otherwise.
5. **Push a PR for review:** When a phase is complete, push a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review before starting the next phase.
6. **Need more context?** If a task references a section not in the phase's Reference list, read just that section on demand.

### Session Tips

- **Don't read everything.** The PRD is large — the phase Reference sections tell the agent exactly what to load.
- **Don't skip tasks.** They're ordered to resolve dependencies.
- **Verify after each phase.** Run the app on a device before moving on (push, camera, and IAP need a physical device).
- **Review before moving on.** Don't start the next phase until the PR is reviewed/merged.
- **Update the status line.** After completing tasks, update `**Status:** X/72 tasks complete` and `**Current Phase:**`.

### Prompt Templates

**Starting a new phase:**

> "Read docs/product-roadmap.md and find the current phase. Read only the Reference sections listed for that phase from docs/prd.md, docs/product-vision.md, and docs/design.md. Start on the first unchecked task. After completing each task, update its checkbox to [x] in the roadmap. Continue through the phase."

**Resuming after a break:**

> "Read docs/product-roadmap.md. Find the first unchecked task. Read only the Reference sections listed for the current phase. Continue from there."

**After completing a phase:**

> "Phase [N] is complete. Create a branch `phase-{N}/{slug}`, commit all work, push, and open a PR targeting main titled 'Phase {N}: {Title}' with the phase goal and completed task count in the body."

**Fixing an issue:**

> "There's a problem with [description]. Read the relevant section of docs/prd.md for the expected behavior and fix it. Don't mark new tasks complete until the fix is verified."

### Phase Review Workflow

After each phase, push the work as a PR and let an automated review agent (default: [CodeRabbit](https://coderabbit.ai) — free for open source) review before merging. Branch per phase: `phase-{N}/{slug}`. Address feedback in follow-up commits on the same branch; merge only when clean. If you don't use GitHub, you can skip this — but you lose automated catching of bugs, security issues, and style problems the coding agent may miss. Per-task verification still applies.
